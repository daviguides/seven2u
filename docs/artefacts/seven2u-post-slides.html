The problem

Five series in rotation. Which episode was I on? Was that one worth it? Is the next one?

Trackers remember checkboxes. Ratings sites remember opinions. Nobody tells you what an episode is before you press play.

The solution

Search. Track. Insight. One surface, one port.

search
TVMaze, live

300ms debounce, AbortController, poster grid with rating and genres. Catalogue is never mirrored; 300s TTL cache.

track
Watched + notes

Two Postgres tables. Optimistic toggle with rollback, per-season progress bars, notes on series or episode.

insight
Spoiler-free AI preview

Agno agent on Groq, 2.5s budget. Heuristic summary when the model is absent, labelled honestly.

Architecture

Clean Architecture. Domain owns the ports, infrastructure implements them.

api/dependencies.py — composition root
The only place adapters are instantiated. Builds TVMazeGateway, SQL repos, GroqProvider; injects into services via FastAPI Depends.
api
routes, DTOs with from_domain(), domain error → 404/422/502
services
series · tracking · comment · insight. Constructor-injected Protocols. No HTTP, no SQL
infrastructure
TVMazeGateway (httpx+cache), SqlWatched/CommentRepository, GroqProvider (Agno), Heuristic
tests/fakes.py
FakeCatalog, FakeWatched, FakeComment, StubProvider: drop-ins for every Protocol
domain
Frozen Pydantic models · Protocols SeriesCatalog · WatchedRepository · CommentRepository · InsightProvider · group_by_season · errors. Depends on nothing above it.

AI component

One Protocol. Agno on Groq. The page never breaks.

Isolation
InsightProvider
generate_insight(ctx) -> SeriesInsight. Services see nothing else. New vendor = new file. Tests use a fake agent; zero network.

Heuristic
Synopsis excerpt + genre tone (25 genres) + rating signal + progress phase + note count. Deterministic. UI badge: AI vs smart summary.
Data model

Two tables. Own only what the user creates.

-- idempotent by construction
CREATE TABLE watched_episodes (
  episode_id  INTEGER PRIMARY KEY,
  series_id   INTEGER NOT NULL,   -- indexed
  watched_at  TIMESTAMPTZ NOT NULL
              DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE comments (
  id          UUID PRIMARY KEY,
  series_id   INTEGER NOT NULL,
  episode_id  INTEGER,  -- NULL = series note
  content     TEXT NOT NULL
              CHECK (length(trim(content)) > 0),
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_comments_target
  ON comments (series_id, episode_id);

No FK to TVMaze. TrackingService checks the episode belongs to the series before writing. PUT watched=true twice returns the same watched_at; false on an absent row is a no-op.
