1. Overview

Seven2U ("Seven" = seventh art, "2U" = to you) is the series module of an early-stage streaming platform. A user searches for a series, opens its detail page, sees episodes grouped by season, marks episodes watched, leaves comments on the series or an episode, and asks for an AI insight that describes tone, themes and what to expect, without spoilers.

Series catalogue data is never stored: TVMaze is the source of truth for shows and episodes. Seven2U persists only what the user creates (watched state, comments) and joins it onto TVMaze data at read time. The AI provider sits behind a Protocol and degrades to a template-based insight when the LLM is unavailable, so the feature never breaks the page.

Design principles
  • Dependencies point inward. api → services → repositories → infrastructure, with domain shared by all and depending on nothing.
  • Own only user data. TVMaze IDs are foreign references; we never mirror the catalogue.
  • AI is a plug, not a pillar. InsightProvider Protocol; HuggingFace is one implementation; a template provider is the fallback. The page renders with or without it.
  • Boring tools, sharp boundaries. FastAPI, SQLAlchemy, httpx, Pydantic, React + Vite + Tailwind. No framework where a function will do.
  • Testable by construction. Services take Protocols; tests inject in-memory fakes. No mocking framework needed for domain and service tests.

2. Architecture

Dependency rule

servicesdomain, repositoriesUse cases: search, detail with progress, toggle watched, add comment, generate insightKnow about HTTP status codes or request objects

SOLID in practice

S: one use case per service methodTrackingService.toggle_watched does one thing. Seasons grouping lives in domain/progress.py, not in the route.
O: new AI provider = new fileAdding Ollama or OpenAI means one class implementing InsightProvider. No existing code changes.
L: fakes are drop-insInMemoryWatchedRepository satisfies the same Protocol as the SQLAlchemy one; services cannot tell them apart.
I + D: small Protocols, injectedShowCatalog, WatchedRepository, CommentRepository, InsightProvider. Services receive them via constructor; FastAPI Depends builds them.

from dataclasses import dataclass, field
from datetime import datetime
from enum import StrEnum


@dataclass(frozen=True, slots=True)
class Series:
    id: int
    name: str
    summary: str | None
    genres: tuple[str, ...]
    premiered: str | None
    image_url: str | None
    rating: float | None


@dataclass(frozen=True, slots=True)
class Episode:
    id: int
    show_id: int
    season: int
    number: int
    name: str
    summary: str | None
    airdate: str | None
    image_url: str | None


class CommentTarget(StrEnum):
    SHOW = "show"
    EPISODE = "episode"


@dataclass(frozen=True, slots=True)
class Comment:
    id: int
    target_type: CommentTarget
    target_id: int
    body: str
    created_at: datetime


@dataclass(frozen=True, slots=True)
class WatchedEpisode:
    episode_id: int
    show_id: int
    watched_at: datetime

Domain models are frozen dataclasses, not Pydantic. Pydantic lives at the boundaries (api/schemas, config.py). This keeps the domain free of validation-library semantics and keeps mypy strict.

Pure domain rules

# app/domain/progress.py
@dataclass(frozen=True, slots=True)
class SeasonProgress:
    season: int
    episodes: tuple[Episode, ...]
    watched_ids: frozenset[int]

    @property
    def completion(self) -> float:
        if not self.episodes:
            return 0.0
        return len(self.watched_ids & {e.id for e in self.episodes}) / len(self.episodes)


def group_by_season(
    episodes: Iterable[Episode], watched_ids: frozenset[int]
) -> list[SeasonProgress]: ...

Repository Protocols

# app/repositories/protocols.py
class ShowCatalog(Protocol):
    async def search(self, query: str) -> list[Series]: ...
    async def get(self, show_id: int) -> Series: ...          # raises NotFoundError
    async def episodes(self, show_id: int) -> list[Episode]: ...


class WatchedRepository(Protocol):
    async def ids_for_show(self, show_id: int) -> frozenset[int]: ...
    async def mark(self, show_id: int, episode_id: int) -> WatchedEpisode: ...
    async def unmark(self, episode_id: int) -> None: ...


class CommentRepository(Protocol):
    async def add(self, target: CommentTarget, target_id: int, body: str) -> Comment: ...
    async def list_for(self, target: CommentTarget, target_id: int) -> list[Comment]: ...

Hooks

function useSearch(query: string): {
  results: SeriesSummary[]; status: "idle" | "loading" | "ok" | "error";
}
// 300ms debounce; AbortController cancels stale requests; empty query = idle

function useSeriesDetail(showId: number): {
  series?: SeriesDetail; seasons?: SeasonOut[]; status; retry(): void;
}

function useEpisodeTracking(showId: number, seasons: SeasonOut[]): {
  seasons: SeasonOut[]; toggle(episodeId: number): Promise<void>;
}
// optimistic: flips watched + recomputes completion locally, PUT, rollback + toast on failure

function useInsight(key: string, url: string): {
  insight?: InsightOut; status; load(): void;
}

State management

No global store. Server state lives in feature hooks (useState + useEffect) with a tiny in-memory cache for insights. The app has two routes and no cross-feature shared state beyond the show ID in the URL, so Redux/Zustand/TanStack Query would be weight without benefit. If a third surface appeared (a "my shows" dashboard), TanStack Query is the upgrade path.

6. AI Integration

Protocol

# app/infrastructure/ai/protocol.py
@dataclass(frozen=True, slots=True)
class InsightRequest:
    subject: Literal["series", "episode"]
    title: str
    summary: str | None
    genres: tuple[str, ...]
    user_comments: tuple[str, ...] = ()
    episode_code: str | None = None      # "S01E02"


@dataclass(frozen=True, slots=True)
class Insight:
    text: str
    provider: str


class InsightProvider(Protocol):
    name: str
    async def generate(self, request: InsightRequest) -> Insight: ...

Implementations

ProviderFileBehaviour
HuggingFaceInsightProviderinfrastructure/ai/huggingface.pyPOST to HF Inference API (chat-completions endpoint, model from HF_MODEL, default an instruct model). Prompt from prompt.py. Returns trimmed text; raises on non-200 or empty
TemplateInsightProviderinfrastructure/ai/template.pyPure function of the request: genre-driven tone sentence + first two sentences of summary + "N viewers left notes" line. No network. Deterministic (tested exactly)
ResilientInsightProviderinfrastructure/ai/resilient.pyWraps primary + fallback. asyncio.wait_for(primary, timeout); on TimeoutError or any Exception, logs and returns fallback result. Also used when HF_API_TOKEN is unset (primary = None)

Prompt policy

SYSTEM: You are a TV critic writing a short, spoiler-free preview.
        Describe tone, themes and what kind of viewer will enjoy it.
        Max 120 words. Never reveal plot outcomes.
USER:   Title: {title} {episode_code}
        Genres: {genres}
        Official summary: <<<{summary}>>>
        Viewer notes (may be empty): <<<{comments}>>>

Summary and comments are wrapped in delimiters and passed as data. Comment text is user input; the prompt instructs the model to treat it as notes, and the output is rendered as plain text (never HTML) on the frontend.

Why HuggingFace as defaultFree tier, no credit card, a single token in .env. The evaluator can run the app with zero AI config (template fallback) or with one env var (real LLM). Both paths return the same schema.

7. Data Model

-- db/init.sql (applied by init_db() on startup via SQLAlchemy metadata.create_all)
CREATE TABLE watched_episodes (
    id          SERIAL PRIMARY KEY,
    show_id     INTEGER     NOT NULL,
    episode_id  INTEGER     NOT NULL UNIQUE,
    watched_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_watched_show ON watched_episodes (show_id);

CREATE TABLE comments (
    id           SERIAL PRIMARY KEY,
    target_type  VARCHAR(8)  NOT NULL CHECK (target_type IN ('show','episode')),
    target_id    INTEGER     NOT NULL,
    body         TEXT        NOT NULL CHECK (length(body) BETWEEN 1 AND 2000),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_comments_target ON comments (target_type, target_id, created_at);

Decisions

ChoiceAlternativeWhy
Single-user, no user_idUsers table + authExplicit non-goal in the challenge. Adding user_id later is a column + index, not a redesign
Polymorphic comments (target_type + id)Two tablesOne repository, one route family, one UI component. CHECK keeps it honest
No catalogue cache tableMirror shows/episodesKeeps DB tiny and always fresh. TVMaze rate limits are generous for interactive use; an in-process TTL cache in the client covers repeats
create_all on startupAlembicTwo tables, greenfield. Alembic is listed as the upgrade path in README

8. Security

Input validation at the edgePydantic on every body and query. q 1..100 chars; comment body 1..2000; IDs are positive ints via path types. Domain re-checks invariants it cares about (empty body) so services are safe without HTTP.
Secrets never reach the browserHF_API_TOKEN lives only in the backend container env. The frontend talks to /api; the backend talks to HuggingFace and TVMaze. Vite has no VITE_* secret.
Upstream failures are containedhttpx timeouts (5s TVMaze, 8s HF). TVMaze errors map to 502 with a generic message; stack traces are logged, not returned. AI errors map to fallback, never 5xx.
Untrusted text is dataTVMaze summaries are HTML: stripped server-side. Comments are rendered as text nodes in React, never dangerouslySetInnerHTML. Comments enter prompts inside delimiters.

CORS is enabled only for the Vite dev origin (localhost:5173) and only in APP_ENV=dev. In compose the SPA and API share one origin so no CORS is needed. SQL goes through SQLAlchemy parameters; no string SQL anywhere.
